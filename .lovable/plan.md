# نظام مشتريات احترافي متكامل

تدفق العمل (Workflow) عبر ثلاث صفحات مترابطة، مع تتبّع منشئ الطلب والمعتمد في كل مرحلة.

```text
صفحة الموردين            صفحة المشتريات              صفحة الفواتير
────────────────         ──────────────────         ────────────────
[طلب شراء جديد]   تعميد   [يظهر الطلب كاملاً]  تعميد   [فاتورة مرتبطة]
 مورد + مشروع    ─────►    + إرفاق ملفات      ─────►   رقم الطلب +
 + كل الأصناف   (المرحلة1)  + مراجعة          (نهائي)   رقم الفاتورة
```

## المراحل والحالات (status)

سيتم توحيد دورة حياة الطلب عبر حقل `status` في جدول `purchases`:

1. `في انتظار الموافقة` — أُنشئ من صفحة الموردين.
2. `معتمد` — بعد التعميد الأول؛ يظهر بالكامل في صفحة المشتريات مع إمكانية إرفاق الملفات.
3. `محوّل لفاتورة` — بعد التعميد النهائي من المستخدم الرئيسي؛ تُنشأ فاتورة وتظهر في صفحة الفواتير.

## 1) صفحة الموردين — بدء طلب الشراء

- إضافة زر **"طلب شراء"** بجانب كل مورد (أو زر عام أعلى الصفحة) يفتح `PurchaseForm`.
- عند الفتح من المورد، يُملأ اسم المورد تلقائياً.
- النموذج يحتوي مسبقاً على: المشروع، طالب الشراء، الأصناف والكميات والأسعار (موجود في `PurchaseForm`).
- يُحفظ بحالة `في انتظار الموافقة` ويُسجَّل `requested_by` و `user_id` (منشئ الطلب).

## 2) صفحة المشتريات — العرض والتعميد وإرفاق الملفات

- تعرض كل الطلبات ببياناتها كاملة (الأصناف عبر `purchase_items`).
- زر **"تعميد"** (للمستخدم صاحب صلاحية المشتريات) يحوّل الحالة إلى `معتمد` ويسجّل `approved_by` = اسم/توقيع المستخدم الحالي.
- إمكانية **إرفاق ملفات** للطلب المعتمد (الحقول `attached_file_url` / `attached_file_name` موجودة) عبر `FileUpload`.
- زر **"تحويل إلى فاتورة"** (موجود) يبقى متاحاً للطلبات المعتمدة، ويقوم بالتعميد النهائي.

## 3) صفحة الفواتير — الربط والعرض

- عند التحويل، تُنشأ فاتورة عبر `useInvoices.createInvoice` تحمل `purchase_id`، اسم المورد، المبلغ، المشروع، الأصناف في الوصف، وحالة `غير مدفوع`.
- إضافة عمود **"رقم الطلب"** في جدول الفواتير يعرض `order_number` للطلب المرتبط (عبر `purchase_id`).
- تغيير حالة الطلب الأصلي إلى `محوّل لفاتورة` لمنع الالتباس، مع شارة "تم التحويل".

## التتبّع (منشئ/معتمد الطلب)

- `requested_by` = اسم منشئ الطلب (يُعرض في كل المراحل وفي طباعة الفاتورة).
- `approved_by` = اسم/توقيع المعتمد (يُعبّأ تلقائياً من المستخدم الحالي عند التعميد باستخدام `userDisplayNames`/`userSignatures`).
- تظهر هذه الأسماء في صفحتي المشتريات والفواتير.

## التفاصيل التقنية

- لا حاجة لتغييرات قاعدة بيانات كبيرة: `purchase_id` على `invoices` موجود. سنضيف فقط (إن لزم) قيمة حالة جديدة `محوّل لفاتورة` (نص حر، لا قيود enum).
- ملفات سيتم تعديلها:
  - `src/components/SuppliersPage.tsx` — زر "طلب شراء" + فتح `PurchaseForm` مع تعبئة المورد.
  - `src/components/forms/PurchaseForm.tsx` — قبول `defaultSupplierName` اختياري.
  - `src/components/PurchasesPage.tsx` — زر "تعميد"، إرفاق ملفات، وضبط زر التحويل ليحدّث الحالة إلى `محوّل لفاتورة` ويسجّل المعتمد.
  - `src/components/InvoicesPage.tsx` — عمود "رقم الطلب" المرتبط.
  - `src/hooks/usePurchases.tsx` — (إن لزم) دالة تعميد مختصرة.
- الصلاحيات: استخدام `PermissionButton` (تعميد/تحويل = `create`/`edit`)، وكل صفحة ملفوفة بـ `ProtectedPage` (متوافق مع نظام RBAC الحالي).
- التواريخ بصيغة ميلادية DD/MM/YYYY، وتعقيم نصوص الطباعة بـ `escapeHtml`.

## خارج النطاق

- لا تغيير على نموذج المحاسبة/القيود الموجود.
- لا إشعارات واتساب (مهجورة).
